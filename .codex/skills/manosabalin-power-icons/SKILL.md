# ManosabaLin 能力图标（Power Icon）产线

## 0. 铁律：能力图标 ≠ 卡图

**不要套卡图那套「粗黑墨描边 / 限色五色 / 平色块背景 / 丝网印刷」规则。**
能力图标是另一套完全不同的语言，且必须照**原版实测规格**来。把原版图标按卡图规则描述，会做出完全不对的东西（2026-10-11 踩过）。

参考语料（已落盘）：`.local/vanilla_power_icons/REFERENCE.md`（原版实测规格 + 全量状态↔效果对照表）
原版图标素材：`.local/vanilla_power_icons/raw/*.png`（72 张 64px 原版图）
         对照图：`.local/vanilla_power_icons/contact_dark.png` / `contact_checker.png` / `onwhite_white.png`

## 1. 原版规格（实测 72 张得出，2026-10-11）

| 项 | 值 |
|---|---|
| 尺寸 | 小 **64×64** / 大 **256×256**（mod 现有 big 也已是 256） |
| 通道 | RGBA，**背景完全透明**（四角 α=0） |
| 实心图形占比 | 平均 44.5% |
| 图形最大边/画幅 | 平均 **0.89**（0.78~0.94） |
| 轮廓 | **半透明近黑柔边**：α 中位 **136**、RGB ≈ (29,27,23)。**不是**不透明粗黑描边 |
| 主色簇 | 众数 **2**（主色 + 同色系暗调≈主色亮度 60%），硬边平涂无渐变 |
| 主色明度 | 高。参照亮红 `#ff494a`（lum≈127）、亮绿 `#94db6b`、亮黄 `#f8c828` |

⚠️ **别被深色底骗了**：原版图标贴深底会看到明显暗边、贴白底表现为中性灰晕 —— 这正是「半透明黑影」的签名，
不是「不透明黑描边」。判断依据要用白底对照。

## 2. 生成（ImageGen）

- 逐张出**白底**平涂符号图，1024×1024，quality high。
- ⚠️ `background: "transparent"` **参数不生效**（实测输出仍是不透明白底 RGB）⇒ 必须自己抠。
- ⚠️ `output_dir` **不保证逐次生效**（同一批多次生成可能落进同一目录、文件名还会撞车覆盖）⇒
  **在提示词开头加 `【标签】` 前缀**，让文件名带上唯一标签；认图靠文件名而不是目录名。
- 提示词骨架（换「主体」与「含义」两段即可）：

```
【标签】Slay the Spire 2 官方游戏状态图标（power icon）风格的一枚正方形图标。

主体：<一句话描述几何上可复现的符号：形状 + 部件 + 相对位置>

画面：单个符号居中，最大边约占画幅 88%，剪影必须一眼可读、能准确表达含义；允许适度的
内部结构与装饰细节（2~4 个小结构元素），但不要让画面变碎变糊。

上色（严格照原版塔二能力图标）：平涂、硬边、无渐变，整枚图标用 2~4 个平涂色块（一个明亮高饱和的
主色 + 同色系暗调压在形体右侧/下方当阴影 + 至多 2 个小面积点缀色，可含纯黑与纯白）。主色必须明亮、
高饱和、高明度（明度像 #ff4a4a 亮红 / #ffc229 亮黄 / #94db6b 亮绿）。绝不要暗沉、浑浊、发黑、发棕、
酒红这类整体发暗的色调，整体观感明快鲜亮。

轮廓：图形外缘包一圈约 2 像素（按 64 像素小图标计）的半透明近黑柔边（黑色约五成不透明度）。

背景：干净的纯白底，不要底板、圆形底、方形底、边框、投影、外发光、光晕。

禁止：画面中出现任何文字、汉字、字母、数字或带字的印章（印章/牌面/书页内部只用几何花纹或空白）；
logo、水印、签名、真人、人脸五官、照片感、3D 渲染、渐变、噪点、厚涂笔触。
```

⭐ **「含义：<效果>」这一句是关键**（2026-10-11 追加要求「剪影要符合效果」）：
在每个图标的主体后加一行 `含义：<该能力的实际效果，直接抄本地化文案的要点>`，
模型会据此补足/修正部件。用户明确说过：**不要刻意简约，形体复杂一点是允许的**——
所以「2~4 个小结构元素」的额度要用上，别退化成单个几何块。

### 高频失败模式（都要在提示词里点名挡住）

| 失败 | 例子（2026-10-11 实测） | 对策 |
|---|---|---|
| 主色发暗发浊 | 塔画成暗棕、帽子画成酒红 | 点名「明度像 #ff4a4a / #ffc229」，明确禁止暗沉/浑浊/发棕/酒红 |
| 剪影不像那个东西 | 「多面体巨石叠成的高塔」→ 软冰淇淋锥 | 用**几何可复现**的描述（「下一条横向宽帽檐 + 上面一个三角尖」） |
| 剪影变成另一种东西 | 魔女尖帽 → 三叉火焰 | 写「绝对重要：必须一眼认成 X，不要画成 Y / Z」 |
| 加文字/印章字 | 纸页上被画上「作废」 | 禁止条款单列「任何文字、汉字、字母、数字或带字的印章」 |
| 部件数量错 | 「两只手递丝带」画成四只手 | 明写「画面里只有两只手」 |
| 部件悬空/脱节 | 帽下飘着无来源的火苗 | 写「必须与帽子相连，不能悬空」 |
| 画成数字/符号 | 烙印裂缝被画成数字 8 | 写「不要出现任何数字、字母或符号形状」 |

### 重做流程

同一张图标可能要改 2~3 轮（实测魔女帽改了 3 轮才对）。约定：
- 重做图仍放 `gen/`，文件名前缀依次用 `【重做-标签】`、`【重做2-标签】`、`【重做3-标签】`。
- `build_all.py` 的 `label_of()` 按 `重做(\d*)_` 前缀解析优先级（数字越大越新），自动取最新版。


## 3. 后处理（`.local/power_icons_v2/postprocess.py`）

```
python postprocess.py <src.png> <输出名=类名小写> <输出目录>
```

做四件事：
1. **抠白底**：`silhouette()` 只吃掉**连通到边框**的近白（阈值 224），再 `binary_fill_holes` 保住图形内部的白高光。
2. **缩放到实心最大边 = 0.89 × 画幅**，居中贴透明画布。
3. ⭐ **在目标尺寸上再套轮廓**（关键）：在 1024 上生成轮廓再下采样，会把半透明环**削薄**（实测 α 从 134 掉到 ~90）。
   正确做法 = 先把主体缩到目标尺寸，再 `binary_dilation(实心, R)` 取 `R = 0.031 × 画幅`（64 下 2px、256 下 8px），
   环填 `alpha = 0.47 × 255`（实测量得 ≈143，对应原版 136）。
4. **预乘 alpha 降采样**（`_resize_premul`），否则半透明边缘会被 LANCZOS 咬出暗边。
   ⭐ 小图**直接从源图渲到 64**，不要再从 256 缩一次（会二次损失）。

自检（必做）：
```
实心% ≈ 40~48 | 最大边/画幅 ≈ 0.88~0.89 | 轮廓环 α ≈ 130~150 | 主色簇 = 2 | 主色 lum ≳ 100
```

## 3b. 批量驱动（`build_all.py`）

```
python build_all.py          # 扫 gen/ -> 按标签映射类名 -> 出 256/64 到 out/
```

- `LABEL2CLASS`：标签 → 能力类名小写（= 落地产物文件名），位于脚本顶部，新增图标时往里加一行。
- 生成图放 `gen/`，文件名形如 `_【标签】_Slay_the_Spire_2_...png`；重做版 `_【重做N-标签】_...`。
- 脚本会打印 `产出 N 个类名` 与「⚠️ 缺图 / ⚠️ 未匹配的文件」，**缺图必须为 0 才继续**。
- 设计表（每个图标画什么、为什么这么画）记在 `.local/power_icons_v2/DESIGN.md`。

## 4. 落地

- 小图 → `ManosabaLin/images/powers/<类名小写>.png`（如 `yalisalintowerpower.png`）
- 大图 → `ManosabaLin/images/powers/big/<类名小写>.png`
- 图标由能力基类按 **`{类名小写}.png`** 解析，**丢进去同名即可生效**，不用改代码。
- ⚠️★ **文件名必须严格全小写**（`GetType().Name.ToLowerInvariant()`）。Windows 磁盘和 Godot 编辑器不区分大小写
  ⇒ 写错大小写**在编辑器里照样能加载、肉眼看不出问题**；但导出成 PCK 后 **Godot 的资源查找严格区分大小写**，
  全小写路径直接 miss、回落通用 `power.png`。
  实测（2026-10-11，`.local/pck_case_probe/`）：把 mod 的 pck `load_resource_pack` 进空白工程后，
  `ResourceLoader.exists("…/originalsinemaregretwitchonhplosspower.png")` = `false`，
  而带大写 L 的原样路径 = `true`。⇒ 事故案例：`…hpLosspower.png` 多了个大写 L，悔恨图标在游戏里一直不显示。
  `audit_missing.py` 用「**实际文件名** vs 类名小写」比对，能自动抓出这类大小写错位（会显示为「缺图标」）。
  修复：重命名 png（含 `big/`）→ 删旧 `.import`（`source_file`/`dest_files` 都写着旧名，且 ctex 路径哈希随源路径变）
  → `--headless --import` 重导入 → 重 publish。
- **必须重发布**（`dotnet publish -c Release`，游戏需关闭）才进 PCK。
- ⚠️ 缺图标会回落通用 `power.png`；小图**必须 64×64**，拿大图当小图会撑爆整排图标槽。
- 核验：PCK 字节搜 `<类名小写>.png` 命中即进包。

## 5. 附：本项目原有的图标是什么样（别被带偏）

`images/powers/` 里原有的 121 张**大多是角色立绘裁切/插画**，甚至有不透明方图与带文字的小牌，
并不是原版那种扁平符号。所以按本产线新做的图标会**与旧图标观感不一致**——这是有意为之（照原版），
不是 bug。2026-10-11 已按用户要求批量替换了 35 个原本回落 `power.png` 的能力（亚里沙 17 / Common 5 /
艾玛 6 / 希罗 4 / 雪莉 3），旧的那批未动。
